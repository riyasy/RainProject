File Version Upgrade Notes

	Version Update Checklist:
	[ ] let-it-rain\version.h              - VER_MAJOR / VER_MINOR / VER_PATCH / VER_BUILD
	[ ] let-it-rain\version.h              - VER_NUMBER X,X,X,X  (commas, for VERSIONINFO)
	[ ] let-it-rain\version.h              - VER_STRING  "X.X.X.X"
	[ ] let-it-rain\version.h              - VER_DISPLAY "v X.X.X.X"  (what the About box shows)
	[ ] LetItRainInstallerMSIX\Package.appxmanifest - Version="X.X.X.X"

	let-it-rain.rc no longer carries a version of its own: the VERSIONINFO block
	and the About dialog's label both read version.h, so the exe's properties
	sheet and its About box cannot disagree. The appxmanifest is XML and cannot
	include a C header, so it stays the one place that must be edited by hand.

	If you edit the dialogs in the VS resource editor, check afterwards that the
	VER_* macros are still macros: the editor may resolve them to literals on
	save, which quietly reintroduces the drift version.h exists to prevent.

void RainWindow::HandleCPULoadChange(HWND hWnd)
{
	static int cpuFreeCycles = 1;
	static bool windowHidden = false;
	if (CPUUsageTracker::getInstance().GetCPUUsage() > 80)
	{
		if (!windowHidden)
		{
			cpuFreeCycles = 0;
			cpuIsBusy = true;
			ShowWindow(hWnd, SW_HIDE);
			windowHidden = true;
			if (!RainDrops.empty())
			{
				RainDrops.clear();
			}
		}
	}
	else
	{
		cpuFreeCycles++;
		if (cpuFreeCycles > 3)
		{
			RainWindow* pThis = reinterpret_cast<RainWindow*>(GetWindowLongPtr(hWnd, GWLP_USERDATA));
			pThis->cpuIsBusy = false;
			ShowWindow(hWnd, SW_SHOW);
			windowHidden = false;
		}
	}
}
